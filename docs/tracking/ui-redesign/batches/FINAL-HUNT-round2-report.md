## Needs the owner's call (found by the journeys, not built)
- **Offline edits to jobs and projects can be lost on a second device.** Jobs and projects merge by whole item, newer `updatedAt` wins (`planFirstSync`); a project is one document with all its issues. An edit made offline on one device to a job or project that the other device edited later is dropped with no notice and no conflict copy (résumés do get conflict copies, `cloudSyncLineage`). Two devices adding issues to one project offline lose the older side's issues. This is the design in `boardActions.js` (per-board last write wins), not a regression.
- **A bookmarked editor link on an empty second device** (`/resume/:id` opened right after sign-in, before the first cloud sync has brought the résumé) lands on the Documents page (`useOpenResume.js:18`). Jobs and boards recover on their own because they are reactive; the editor does not. A safe fix needs the auth-loading and first-sync-done signals plus a way out when the sync never answers.
- **Custom interview stages** ('Your Stages') live only in the browser (`jobStages.js`): they are not synced and not removed at sign-out, so a shared browser shows the previous account's stage names.
- **List view's `+ Create issue`** on a Scrum project with a running sprint puts the issue in the backlog, while the board column and the Create dialog put it in the active sprint (intent unclear).
