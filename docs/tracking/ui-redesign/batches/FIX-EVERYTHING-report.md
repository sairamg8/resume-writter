## What the reviews changed (so these are NOT in the list above as shipped)
- **S7, 500-write batches: REVERTED.** Splitting a sync into several non-atomic requests opens data-loss paths (a partial failure then Undo; batches landing out of order; a winner and its conflict copy split across batches). The old behaviour is slower for lists over 500 items (one request per item) but safe, so it stays. Not built: a safe multi-batch sync would need a transaction design.
- **S4, stale writes: NARROWED.** Only `importJobs` and `moveJob` take another tab's in-flight save in first. The `replaceJobs` part was dropped: on sign-out it kept another tab's job in a list that is meant to be emptied, for the next account to upload.
- **U4, floating panels: REWRITTEN.** The first version cleared the panel's height cap to measure it, which made a scrolling menu jump to its top on every scroll event (found by the `[xhigh]` review). It now reads the height off the content and never touches the cap.
- **S1, conflict copies: HARDENED** after the sync review: copy ids are deterministic (two tabs or devices make the same copy, not two), a star or colour change alone is not a conflict, and the notice names are cleared in every tab on sign-out.
- **P1:** the issue dialog's Sprint field no longer offers Backlog for a done issue in a sprint (the drag and Move-to paths were already refused). **U7:** the Job Tracker's shortcut sheet keeps the true Enter/Space hint.

## Not fixed, on purpose (owner's call or limits that remain)
- **Offline edits to the SAME job or project on two devices:** the newer copy stays and the older is kept as a '(conflict copy)' with a notice. Still not caught: an item with no recorded sync version (a sample/demo job edited on two browsers), a device whose clock is behind (its edit looks older, no copy), two devices committing at the very same moment (last write wins, no precondition), an edit made during the few seconds a sync is reading the cloud. A harmless extra copy can appear after an interrupted save. Doing better needs a transaction/precondition design.
- **Unreadable list from another tab (S6):** the tab shows a recovery notice and forgets the sync record, so the next first sync will not delete the account's copies, but that tab's live sync can still queue the dropped items as deletions. Pre-existing path; rare (a damaged value or a skewed deploy).
- **Interview stages (S3):** a stage removed on one device can come back from another that still holds it (no tombstones); the first form open of a new account can carry the browser's old stage names once (names only).
- **Phone project pages (U1):** the page now scrolls as one on a phone, so the table header, the timeline day header and the swimlane header no longer stick there (they do from md up).
- **PDF tall item (U9):** the height estimate is deliberately cautious, so a single bullet over roughly 575 characters in a 4-column cell (about 800 in 3 columns) may now split across a page foot instead of moving whole. Nothing is clipped; summaries and cover letters print as before.
- **Dashboard import of a saved store (S13):** for a demo account the 'import as my original' flag is applied to every résumé in the file. The editor's own import still rejects a raw store file.
- **Not built, not defects:** T3 (the pdfminer test always skips on CI: a known-limit todo), T4 (real-timer and tick-count tests: no failure seen), the empty Documents page after sign-out has no hint (start-up size cap), V1 (a letter linked to a job shows as a letter, which is right).
