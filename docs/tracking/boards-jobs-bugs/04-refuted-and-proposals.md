# Refuted findings and the redesign proposals

> Part of [README.md](README.md). Status: 🔴 open · ⏸ fixed on `boards-jobs-ui` (not merged) · ✅ merged to master · ✖ not a bug.
> Set the row (status + commit + test) in the SAME commit as the fix. Found by WF-1 `wf_a523cc8e-2ca` at `8409472`, 2026-09-23.

## Refuted by the verifiers (kept so they are not re-filed)

- **BL-13** — The Boards feature has no tests (R2-155 / R2-159) — ✖ The facts are true: no test or Cypress spec loads a board module, normalizeBoard.js:6 cites a tests/unit/normalize-board.unit.mjs that does not exist, and _resetBoardStoreForTest is never imported. But a coverage gap is not a defect a user can hit: it has no repro, expected or actual behaviour. Counting it as a bug would inflate the tally. It is kept as a 'must' proposal (Board test suite) that references R2-155 and R2-159.
- **BU-15** — Labels are unnamed colour-only bars that cannot be renamed — ✖ This is the current design, not a defect. Every label's name is its colour (LabelPicker toggles LABEL_COLORS entries such as {name:'Red'}, and constants/boards.js says renaming comes later), so the bar conveys exactly what the label holds. Named labels are a missing feature, now in the proposals. The white check on amber/green swatches (about 2.1:1) is folded into the same proposal, and aria-pressed already exposes the selected state to assistive tech.
- **BU-24** — Links in a card description can never be opened — ✖ Overstated. createLink writes a real <a href>, so on desktop the browser's context menu (right-click → Open link in new tab) opens it. Clicking does not follow it because the description is always contentEditable, which is a missing read view rather than broken behaviour. Kept as part of the 'task editor / issue detail' proposals (a read view with clickable links).
- **JL-21** — 'Active' stat and the job page's 'Apps' count include Saved jobs — ✖ Nothing is miscounted by the code's own definitions. 'Active' is every job that is not rejected, withdrawn, offer or on_hold (JobTracker.jsx:79), and a Saved job is an open item. 'Apps' is an intentional global count of tracked jobs. Whether Saved should count as Active is a product definition, so it moves to the 'Meaningful stats' proposal.
- **JU-11** — Kanban's eight fixed 224px columns overflow, so Offer and the closed columns start off-screen — ✖ The board is an overflow-x-auto container (KanbanView.jsx:166). Every column can be reached by scrolling, as on Jira and Trello, and the status chips scroll straight to a column (146-150). Nothing is lost or broken. This is a layout preference and moves to the responsive layout proposal (flexible columns, collapsed Closed lane).
- **JU-22** — Delete, Clear and Reopen depend on window.confirm and have no undo — ✖ The confirm() calls work as intended. They are dead only after the user tells the browser to suppress dialogs, which is a browser-level choice and not app behaviour. Having no undo is a design choice, not a defect in the code. Moved to the ConfirmDialog/Undo proposal.
- **JU-23** — Header toolbar wraps on phones, and a destructive 'Clear' shares its label with the filter 'Clear' — ✖ This is layout and wording preference. The destructive Clear is guarded by confirm('Clear all jobs and start fresh?') (JobTracker.jsx:163), so the ambiguous label cannot erase data without a prompt. Moved to the responsive layout proposal (one primary action, overflow menu, 'Delete all applications…').
- **JU-27** — Job header shows global, unlabeled counts ('Apps', 'W', 'R') — ✖ The counts are intentional (commented 'Global application counts', JobDetail.jsx:99) and computed correctly. The cryptic single-letter labels and their placement are a design issue. Moved to the stats proposal, which removes the block from the job page.
- **JU-28** — A single click records a status change permanently, with no confirmation, no undo and no history editing — ✖ Recording every status change in statusHistory is the designed behaviour (useJobStore.updateJob), and the status can be moved back from the Pipeline. Undo toasts and editable history are missing features, not code defects. Moved to the 'Status-driven dates and editable history' and 'ConfirmDialog/Undo' proposals.
